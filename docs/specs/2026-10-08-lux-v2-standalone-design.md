# Lux v2 · 独立应用设计（面向 LOL 新手，基于 101.qq.com）

日期：2026-10-08 ｜ 状态：brainstorming 已逐节确认，待用户审阅后进入实施计划

讨论产物（架构图、界面 mockup 草稿）未入库。

## 1. 背景与目标

Lux 全面转向：**放弃** Pengu Loader 客户端插件方案（旧设计/计划文档作废），改为**独立桌面应用**，数据基础为 101.qq.com（腾讯官方国服数据）。

- **目标用户**：刚开始玩英雄联盟、对游戏理解不深的新手。
- **核心价值（选人阶段）**：① 根据当前双方阵容告诉新手选什么英雄；② 该英雄带什么天赋与召唤师技能；③ 一键帮他设置好。对局内出装为后续（v1 不做）。
- **v1 成功标准**：自己跑通 + 打包 Windows 一键安装包，发给新手朋友可用。
- **硬约束**：工作日 9:00–12:00、14:00–18:00 **禁止一切外部 API 调用**（应用运行时 + 开发调试/测试/抓样本，全场景；按本机时间；12–14 点、18 点后、周末不受限）。该约束是产品行为的一部分，由 timeGate 模块强制。（2026-10-09 修订：约束缩小为开发工具；应用运行时随时可同步。）

## 3. 总体架构

组件（图见讨论产物 `architecture.html`）：

- **LCU（游戏客户端）**：选人会话/事件、符文页写入、技能携带、英雄资源（名称/图标/伤害类型/标签/难度/已拥有/熟练度）
- **Lux 主进程（Node）**：LCU 客户端、数据同步器（时段门控）、本地数据仓（按版本快照）、推荐引擎（评分 + 理由）、窗口/托盘管理
- **渲染进程**：置顶小窗 UI、设置页（React）
- **101.qq.com（mlol.qt.qq.com）**：仅被同步器在允许时段访问

数据流：

1. 启动：发现客户端进程 → 读 lockfile → 连上 LCU
2. 同步（仅允许时段）：比对版本/数据日期 → 只抓缺失 → 解析入库 → 记录数据日期
3. 进入选人：LCU 事件推送模式/位置/双方已选 → 推荐引擎查本地数据仓 → 评分 + 生成一句理由
4. 展示：小窗渲染（主推 + 天赋 + 技能）；「详情」展开备选与数据
5. 一键应用：LCU 写入符文页 + 携带召唤师技能（失败则提示手动步骤）
6. 离开选人：小窗隐藏，等待下一局

**关键原则：选人阶段零外部请求。**

## 4. 数据层

### 4.1 数据源（101.qq.com / mlol.qt.qq.com）

| 端点 | 内容 | 状态 |
|---|---|---|
| `GET /go/database/versionlist` | 版本列表 | 解析器已有 |
| `.../lol_101strategy?itier=255&version_id=&lane=` | 梯度榜（按位置） | 解析器已有 |
| `..._confront?lane=&championid=` | 对位（好打/难打各 5） | 解析器已有 |
| `..._partner?lane=&championid=` | 协同（队友搭配） | 解析器已有 |
| 符文 / 大乱斗端点 | 符文组合排行、大乱斗英雄数据 | fixture 已锚定响应形态；**字段语义由「数据侦察」任务锁定** |

- **数据侦察**（实施第 0 步，仅允许时段）：抓线上样本，锁定符文/召唤师技能/大乱斗端点的字段语义与请求参数。
- **召唤师技能**：侦察确认是否存在独立端点；若不存在，兜底 = 内置规则表（按英雄/位置/模式，如闪现 + 点火），不阻塞功能。

### 4.2 本地数据仓

- 存储：JSON 快照文件（按版本）+ 内存索引，不引入数据库。
- 内容：版本号、各端点数据日期、梯度榜（各位置）、对位表、协同表、符文/技能（峡谷按位置；大乱斗）。
- 同步策略：启动时 + 运行期间每 3 小时检查（检查零出网，仅在需要且处于允许时段时抓取）；版本或数据日期变化 → 只抓变化部分；并发 5、节流；失败保留旧快照，下个允许时段重试。
- 规模预估：全量 ≈ 1.7k–2k 请求/版本（对位 + 协同 ≈ 170 英雄 × 5 位置 × 2，符文 ≈ 170，榜单少量），允许窗口内约 2–4 分钟完成；实现时可进一步压缩。

### 4.3 时段门控（timeGate）

- 单一导出 `isApiAllowed(now)`：周一至周五 `09:00 ≤ t < 12:00`、`14:00 ≤ t < 18:00` 为禁；其余允许。按本机时区。
- 所有网络入口（同步器、手动同步按钮、任何调试请求）必须经过它；禁窗内手动同步按钮禁用并提示可用时段。
- 假时钟单测覆盖边界：8:59 / 9:00 / 11:59 / 12:00 / 13:59 / 14:00 / 17:59 / 18:00 + 周六周日。

### 4.4 英雄元数据

- 来源 LCU 资源接口 + 本地缓存（无客户端时用占位数据）。
- 已拥有 + 本周免费清单 → 候选池过滤输入。

## 5. 推荐引擎（纯函数管线）

`buildContext(会话, 数据仓, 英雄元数据) → candidates → scoreAll → rank → explain`

### 5.1 候选池

- 默认只含「已拥有 + 本周免费」（设置可关）
- 征召模式：仅位置匹配的候选
- 剔除已选 / 已 Ban

### 5.2 评分因素（每项 0–100，加权求和）

| 因素 | 来源 | 规则 |
|---|---|---|
| 版本强度 | 101 梯度榜 | rank / winrate / 位置 T 级 归一化 |
| 对位优势 | 101 对位表 | 敌方对位英雄在「好打」名单加分、「难打」减分、未覆盖中性 |
| 队友协同 | 101 协同表 | 队友在搭配名单加分、未覆盖中性 |
| 阵容契合 | 本地规则 | 伤害配比 / 缺前排 / 敌方刺客多→耐揍等，由英雄标签推导 |
| 新手友好 | LCU 熟练度 + 官方难度 + 已拥有 | 轻加权 |

初始权重（集中于配置文件，便于调参）：

- 排位 / 征召：对位 30 / 强度 25 / 阵容 20 / 协同 15 / 新手 10
- 盲选：阵容 45 / 强度 35 / 新手 20
- 大乱斗：强度 40 / 阵容 35 / 新手 25

### 5.3 大乱斗换/留判定

输入：当前英雄 + 备战席 + 剩余骰子数；对「当前 + 备战席」跑同一套评分：

- 备战席最优 − 当前 ≥ 8 分（初始阈值，可调）→「建议换：X」
- 当前为最优或差距小于阈值 →「留着」
- 全部可用英雄总分 < 55（初始阈值）且骰子 > 0 →「建议掷骰子」
- 理由文案同步生成

### 5.4 理由生成（确定性模板，不依赖在线服务）

| 主导因素 | 模板示例 |
|---|---|
| 对位 | 「对线好打：打 {敌方} 胜率 {x}%」 |
| 阵容 | 「你们缺{前排/AP/AD}，{英雄}正好补上」 |
| 强度 | 「版本强势：{模式}胜率 {x}%（{T 级}）」 |
| 协同 | 「和队友 {英雄} 是黄金搭档（胜率 {x}%）」 |
| 新手 | 「你玩得多（{熟练度}）且操作上手简单」 |
| 无数据 | 「适合当前阵容」 |

主导因素 = 加权贡献最大者。

### 5.5 降级

- 单因素缺数据 → 中性 0.5 分，详情页标「部分数据缺失」
- 整仓未就绪（首次运行）→ 规则模式（仅阵容契合 + 新手友好），面板提示同步时机

## 6. LCU 集成

- **连接**：进程/lockfile 发现 → HTTPS REST（自签证书）+ WSS 事件；断线指数退避重连；客户端未运行时静默等待。
- **读**：选人会话（模式、位置、双方 picks/bans、备战席、骰子数）、英雄资源、已拥有/熟练度。
- **写（仅两类）**：符文页创建/应用（`/lol-perks/v1`）；召唤师技能携带（`/lol-champ-select/v1/session/my-selection` PATCH）。失败 → 提示 + 手动步骤。
- **不做任何代打行为**（接受对局 / 选人 / 换人 / 掷骰子）。

## 7. UI（置顶小窗）

- **四状态**：主状态 / 展开详情 / 大乱斗判定 / 收起态（mockup：讨论产物 `ui-states.html`）
- **行为**：置顶、尽量不抢焦点、可拖动、位置记忆、靠边贴靠、收起为药丸条（悬停展开）；离开选人自动隐藏；托盘常驻（显示/隐藏、设置、退出）。
- **视觉**：深蓝 + 金色（贴合客户端语言）；圆角/动效/间距实现期打磨，目标是「尽量美观」。
- **设置页**：候选池开关、模式开关、同步状态 + 手动同步（过 timeGate）、关于/声明。
- **首次启动引导页**：用途、数据同步时段说明、免责声明（第三方工具风险、101 非官方、LCU 读写说明）。

## 8. 测试策略

- 解析层：fixtures 回归（延续现有模式，补符文/大乱斗样本）
- 引擎：纯函数单测（构造阵容，断言排序与理由文案）
- timeGate：假时钟（见 §4.3 边界清单）
- LCU：录制会话快照单测（脱敏）+ 手动联调
- UI：手动冒烟清单（各模式选人、阵容变化重算、断网、客户端重启、禁窗行为）
- 联网测试只在允许时段执行。

## 9. 打包与分发

- electron-builder → NSIS 一键安装包 + 卸载；不签名（SmartScreen 提示在安装说明中告知）。
- 自动更新 v1 不做（新版手动下载安装）。

5. 小窗 UI + 设置 + 引导页
6. 打包 + 朋友试装
